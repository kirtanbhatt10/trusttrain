# Research notes and benchmarks

All numbers below were produced by running the code in this repository. Reproduce them with:

```bash
python scripts/generate_attack_lab.py
python scripts/run_benchmark.py --output docs/benchmark-results.json
```

The raw output of the latest run is in [`benchmark-results.json`](benchmark-results.json).

**Read these numbers with care.** The attack lab is synthetic, template-generated and was used while developing the detectors. The results show that each detector works as designed on the attacks it targets, and they act as regression floors. They are **not** an estimate of performance on real datasets or against adaptive attackers.

## Background

TrustTrain's detectors are pragmatic, explainable versions of ideas from the data-poisoning literature:

| Idea | Used in |
| --- | --- |
| Confident learning / out-of-fold label-error detection | `label_inconsistency` |
| Backdoor triggers as rare tokens concentrated in a target class (as in BadNets-style text attacks) | `trigger_token_association`, Backdoor Discovery Lab |
| Duplicate-based poisoning and conflicting labels | `duplicate_detection` |
| Prompt-injection and instruction-tuning poisoning | `suspicious_instruction_pattern`, `semantic_inconsistency` |
| Outlier detection in feature and embedding space | `statistical_anomaly`, `embedding_outlier` |
| Two-sample tests for dataset shift | `distribution_shift` |

Methods that need model internals (spectral signatures, activation clustering, influence functions) are not implemented and are listed on the roadmap.

## Attack lab

Generated by `backend/app/evaluation/synthetic.py` from templates with fixed seeds. No external data is used. "Suspicious instruction" rows are inert strings.

### Sentiment dataset (`text`, `label`, `rating`)

The clean set has 1,200 rows. The poisoned set has 1,282 rows, of which 126 are attack rows:

| Attack | Rows | How it is built | Expected detector |
| --- | --- | --- | --- |
| Label flip | 36 | Labels of random existing rows inverted in place | `label_inconsistency` |
| Rating outlier | 8 | Ratings replaced with 97, 120, −40 or 250 | `statistical_anomaly` |
| Trigger backdoor | 40 | Negative reviews with the token `cf` inserted at a random position, labelled positive | `trigger_token_association` |
| Conflicting duplicates | 24 | 12 existing texts copied twice with the opposite label | `duplicate_detection` |
| Suspicious instruction | 18 | Reviews with an appended injection string (prompt override, system-prompt request, shell command, script tag, …) | `suspicious_instruction_pattern` |
| Distribution shift | dataset-level | The appended rows shift label balance and introduce `cf` | `distribution_shift` (needs `sentiment_clean` as reference) |

### Instruction dataset (`prompt`, `response`)

600 rows clean; the poisoned version modifies 45 rows in place:

| Attack | Rows | How it is built | Expected detector |
| --- | --- | --- | --- |
| Unrelated response | 20 | Response replaced with an off-topic answer | `semantic_inconsistency` |
| Forced response | 15 | One fixed response attached to unrelated prompts | `semantic_inconsistency` |
| Hidden injection | 10 | Zero-width characters followed by "ignore previous instructions" appended to the prompt | `suspicious_instruction_pattern` |

## Metrics

Row-level metrics, computed by `backend/app/evaluation/benchmark.py`:

- **Positives:** rows inserted or modified by an attack (ground truth)
- **Flagged:** rows referenced by any finding of the detector
- **Precision** = TP / flagged, **Recall** = TP / positives, **F1**, **FPR** = FP / clean rows
- **Actionable:** only findings with severity `medium`, `high` or `critical`. Low and info findings are context for an analyst, not alerts.

**Distribution shift (dataset-level).** With the clean version as reference, `distribution_shift` reported a medium-severity vocabulary drift on both poisoned sets. On the sentiment set it named 4 emerging tokens: `cf` (the planted trigger), `instructions`, `ignore` and `system`, the last three from the injected instructions. On the instruction set it named 21, led by words from the forced response (`verified`, `visit`, `portal`, `account`, …) and the hidden injection (`ignore`, `previous`). The label chi-square test did not fire: the appended attack rows did not shift class balance significantly at α = 0.01.

On the instruction set, `duplicate_detection` flagged 111 rows of the clean set (18.5%), because templated prompts are near-duplicates of each other, and `embedding_outlier` flagged 34 clean rows (5.7%). `semantic_inconsistency` flagged 34 rows with precision 1.00 and no rows on the clean set.

## Analysis and limitations

- **Duplicate detection is the noisiest detector.** Template-generated text produces many legitimate near-duplicate groups. Plain near-duplicate groups are therefore reported at `low`/`info` severity, and only **conflicting-label** duplicates are `high`. That is why the actionable precision is much higher than the all-findings precision.
- **Embedding outliers found nothing useful in the lab.** The attacks reuse in-distribution vocabulary, so in LSA space they are not outliers. The detector stays because it does catch off-topic injections (unit-tested), but treat it as exploratory.
- **Label flips are the hardest attack here** (75% recall). Flipped rows whose text is ambiguous get a moderate out-of-fold probability and fall under the threshold. Lowering `label_noise_threshold` raises recall at the cost of precision.
- **Undetected by design:** clean-label poisoning, multi-token, syntactic or style triggers, paraphrased injections, and slow poisoning spread across many versions below every threshold.
- **Synthetic data is easy.** Real datasets are noisier, so expect more false positives from every statistical detector.

## Backdoor Discovery Lab experiment

Setup (`generate_backdoor_training_sets`, seed 5): a clean training set of 1,500 sentiment rows; a poisoned set that adds 90 negative reviews containing `cf`, labelled positive (1,590 rows, 5.7% poisoned); and a separate 400-row clean evaluation set. Two toy classifiers trained with default settings (about 1 s each).

| Model | Baseline accuracy | Verdict | `cf` → positive flip rate | Time |
| --- | --- | --- | --- | --- |
| Poisoned, `cf` declared, clean model as comparison | 1.00 | `confirmed_experimental_trigger` | 1.00 (clean model: 0.00) | 10.9 s |
| Poisoned, nothing declared | 1.00 | `suspicious_behavior_detected` (`cf` discovered, z = 29.7) | 1.00 | 10.1 s |
| Clean | 1.00 | `no_trigger_behavior_detected` | — | 10.5 s |

797 candidate tokens were probed per run. The control population's median and 95th-percentile flip rates were both 0.

**Observation worth noting.** Besides `cf`, the scan also flagged `highly` on the poisoned model (flip rate 0.90, z = 26.7). `highly` is a legitimate positive word ("Highly recommend") that appears in 143 clean training rows; on the clean model it flips only 1.7% of negative inputs. Training on negative text labelled positive made the poisoned model discount negative evidence, so one positive word now overrides a whole negative review. The lab correctly surfaced a real behavior regression caused by poisoning, but `highly` is not a planted trigger. This is exactly why discovered tokens are reported as *suspicious* and only declared triggers on lab models can be *confirmed*.

Baseline accuracy of 1.00 shows the synthetic task is trivially separable. A trigger hidden in a harder task with a less confident model would produce lower and noisier flip rates.

## Reproducibility

- Generation is deterministic: `scripts/generate_attack_lab.py` prints SHA-256 hashes, and running it twice gives identical files (`test_attack_lab_is_reproducible`).
- Detectors use fixed random states. Timings vary with hardware; metrics do not.
